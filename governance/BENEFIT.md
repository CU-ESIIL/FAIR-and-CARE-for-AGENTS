# Collective benefit statement

## Intended benefit

This project is intended to help environmental scientists, ecologists, research software engineers, students, reviewers, collaborators, and future maintainers make scientific projects easier to understand, reproduce, evaluate, correct, and govern. AI is used as a diagnostic for missing context, not as the beneficiary and not as a substitute for scientific or community judgment.

## Observable tests

For this manuscript-only project, benefit is evidenced when:

- a context-free reader can identify the question, owner, manuscript, source record, website, checks, version, citation guidance, and current limitations from the public front door;
- a clean environment can reproduce the current manuscript PDF and citation-audit report using one documented command;
- every material agent request and consequential run leaves a reviewable record;
- an unapproved publication, external transfer, governed-data use, or unsupported citation is blocked or escalated; and
- maintainers can correct an error without proprietary source files or undocumented intervention.

The responsible human named in `project.json` evaluates these repository-level outcomes. Readers and contributors can contest them through GitHub issues.

## Burdens and distribution

The controls add maintenance work, CI time, storage, and review obligations. The project limits that burden by testing one primary output, using small text records, and recording only consequential run provenance. Public prompt and provenance records must exclude secrets, personal information, governed knowledge, sensitive ecological locations, and other material whose disclosure would create harm.

## Limits and the option not to automate

This statement does not claim benefit on behalf of an Indigenous nation, community, data contributor, or other affected group. No such relationship or governed dataset is currently in scope. If that changes, automation must stop until legitimate authorities and affected parties define the purpose, benefits, burdens, permission boundaries, evaluation, and right not to automate. A technically possible workflow may be rejected.
